## 怎麼掃的

臨時探針：`D:\2026\adb-converter\build\tmp-kepan-scan\main.go`（Go，用 `internal/adb` 解 `source` 區塊：
bzip2 → UTF-16LE）。一本書的邊界是 `<書 …>書名</書>`，正文算到下一本之前。

三個訊號：

| 訊號 | 意思 | 可信度 |
|---|---|---|
| `marks` | 正文出現 `[甲乙丙丁戊己庚辛壬癸][一二三四五六七八九十]` 的次數 | 低——律部「某甲一…」、戒本編號都會中 |
| `ke` | 出現「科判」「科文」字樣的次數 | 中——標題或解說提到科判，通常真的有 |
| `lvl` | `<甲>`…`<癸>` 這種層級**元素**的個數 | 高（有就是被結構化過），但少見 |

```powershell
cd D:\2026\adb-converter
go run ./build/tmp-kepan-scan <adb>            # 預設列出 marks≥6 或 ke≥2 或 lvl≥10
go run ./build/tmp-kepan-scan <adb> ctx 科判    # 看某個詞前後的原文
go run ./build/tmp-kepan-scan <adb> head       # 看開頭，確認結構
```

## 追加（2026-11-05）：沒有「甲一」不代表沒有科判

yjj 的 X24n0246《圓覺經略疏科》全書 **0 個「乙」字**，卻是貨真價實的科文（只用「初／二／三」）。
所以 adb 掃描的 `marks` 欄位只能當「加分」，不能當排除條件；書名帶「科」與 `<科判>` 元素才是主訊號。
