- 科判理论
  - 什么是科判？
    - 科判是一种对经典的注释体例，它将经典依照内容分为数段，再精简扼要地标示各部分的内容，每个被标示的段落被称为“一科”。最初只是将经典并列划为三科，之后人们在大科之下再分细科，细科之下再分细科……就出现了层级式的科判结构。
  - 科判的起源与流变
    - 起源
      - 东晋道安大师（314~385）创“三分科经”，判经中义理可分三大科：序分、正宗分、流通分，时人不信，谓其割裂经义。后来唐朝玄奘大师（602~664）翻译了亲光菩萨的《佛地经论》，里面也将佛经科为三分：教起因缘分、圣教所说分、依教奉行分，与道安大师“三分科经”全同。众人心悦诚服，盛赞其为“弥天高判”，于是今古同遵。
    - 流变
      - 趋于细密
      - 归于简略
      - 失落
        - “科判之研讨乃经师之常课，自古如之，无有特别提倡之一节，只因二百年来西风东渐……我佛义学传承庶几无存矣！”海云继梦《[科判与科註](https://mp.weixin.qq.com/s/ZLKn9QwhqNtcfQWIgqnnLA)》
      - 复兴
        - 我辈自当勉力
  - 科判的组成结构
    - 标题
      - 整个科判的标题，一般直接用所用经典的名称加上“科判”或“科·文”（意为“科判与原文”）组成。
    - 基本信息
      > 即标题下的“Note”
      - 原文及作者
      - 科判版本来源、分科者
      - 录入者
      - 录入时所使用的版本（如是电子版，希望能分享出来）
      - 版本状态（如：未校、一校）、版本号及版本日期
      - 版本更新说明
    - 科判条目
      - 科判序号
        - 天干·地支·千字文（如：乙二、正宗分）
        - 英文字母（如：B2.正宗分）
        - 西方编号（如：2.4.3.1）
        - 语文序号
          - 一、
          - （一）
          - 1.
          - （1）
          - ①/a.
        - 汉语分节
          - 篇
          - 章
          - 节
        - 自编符号（如礼贤法师《法华玄义科文》：■、◆、●、▲、★、□、◇、○、△、☆、◎、¤、⊙、※、≌、§）
      - 条目名称
    - 配合内容
      - 经典原文
      - 原文解释
  - 科判的术语体系
    - 科判表
      > 即是以图表形式呈现的科判，也可称科表、科判、科文（科判文）
    - 科·文
      > 即“科判+原文”的略称
    - 科判的性质
      - 详略/粗细
        > 详/略：科判的层级及科目数量越多，科判越详细，称为“详科”。（粗/细，例然。）
    - 组成
      - 标题
        > 整个科判表的标题
      - 根/根节点
        > 当前显示模式下，层级最高的科节
      - 科节/科目/枝节/科/节点/主题
        > 各个科的泛称，示例：“这张科判表有几千个科目。”
      - 序号/编号
        > 科目的编号
      - 注释/附注
        > 在Dynalist里按Shift + Enter添加注释
      - 层/级/层级
        > 即天干地支等编号所表明的关系：甲级比乙级高一级，乙级比丙级高一级……在Dynalist中，从左至右为层级的深入。
        - 母子级/父子级/上下级/前后级/深浅级/左右级
          > 母=父=上=前=浅=左（可能有些版式的“左级”不是这个意思）
        - 兄弟科/并级/同级
          > 同一级下的各个科节
          - 兄级/弟级（姐级/妹级）
            > 同一层级下，顺序在前的为兄级，在后的为弟级。
        - 分支/分枝
          > 相对某科节而言，其子级就是其分支
    - 操作
      - 收起
        > 使分支被隐藏
      - 展开
        > 使分支显现
      - 下钻/钻入（Zoom in）
        > 进入下钻模式的动作
        - 下钻模式
          > 以任一科节为根节点（即是“钻入”该科节）的显示模式。在XMind里右键选择“下钻”；在MindManager中，此功能被称为“仅显示选中主题及分支”（Show branch alone）；或在Dynalist里按 Ctrl + ] 进入。
      - 上钻/钻出（Zoom out）
        > 在下钻模式时，上钻一级，代表根节点换成该科节的上级。在Dynalist里按 Ctrl + [ 进入。
      - 同级切换
        > 在下钻模式时，根节点换成该科节的同级。在Dynalist里按 Ctrl + Shift + ] 则以弟级为根节点，按 Ctrl + Shift + [ 则反之。
  - 科判的存在形式及其特点
    - 单独原文
      - 没错，单独原文也是可以包含科判的。作者行文虽然已经有了分科意识，但是未将科判列出，因此科判便隐没于原文。这种科判散落在文中，无法用于概览全文结构，只能对其周围的段落起到标识作用。
      - 这种情况可能出现在科判发展较原始的阶段，虽然分科得很成熟，但是没有将其视为一种特殊的文体。也可能是原文结构简单，作者认为不需要单独提出科判。
      - 实际形式也有很多种：
    - 单独科判
      - 科判藏在原文之中，不便于把握文章结构，因此需要单独地将科判列出来。（一般是后人提取、整理前人作品中的科判。）这种单独科判一般出现于对大经大论的细致分科之中，它的出现代表科判的高度发达，毕竟是”科判“这种体例的单独呈现。但是使用的时候还需要另外拿着原文来对照，不便于握持，而且每次使用还需要将科判与原文配对一次。
      - 实际形式也有很多种：
      - 科判高度拆分![会性法师《天台四教仪》科判手稿](https://dynalist.io/u/5zT9D6pvD73JefKEeFENPIEx)
      - 科判基本连在一起，但是被页面截断
    - 科·文对照
      - 这种形式是最为广泛使用的了，有效避免了以上两种的缺点。一般有以下几种形式：
        - 一、类似目录，科判在全书之首。方便概览全文结构，但在阅读原文的时候不便与原文对照。
        - 二、科判分散在文中，但是与原文有明显区分，如换行、缩进、换字体……
        - 三、冠科。这是古人聪明才智的体现，将科判以眉批的方式置于书页上端，既独立出来，又不脱离原文。但是仍然是分散的，方便与原文对照，但不方便通过科判概览全文结构。

      - [数（数据结构）](https://zh.wikipedia.org/wiki/%E6%A0%91_(%E6%95%B0%E6%8D%AE%E7%BB%93%E6%9E%84))
        - 节点的度：一个节点含有的子树的个数称为该节点的度；
        - 兄弟节点：具有相同父节点的节点互称为兄弟节点；
        - 树的度：一棵树中，最大的节点的度称为树的度；
        - 叶节点或终端节点：度为零的节点；
        - 非终端节点或分支节点：度不为零的节点；
        - 父亲节点或父节点：若一个节点含有子节点，则这个节点称为其子节点的父节点；
        - 孩子节点或子节点：一个节点含有的子树的根节点称为该节点的子节点；
        - 节点的层次：从根开始定义起，根为第1层，根的子节点为第2层，以此类推；
        - 树的高度或深度：树中节点的最大层次；
        - 堂兄弟节点：父节点在同一层的节点互为堂兄弟；
        - 节点的祖先：从根到该节点所经分支上的所有节点；
        - 子孙：以某节点为根的子树中任一节点都称为该节点的子孙。
        - 森林：由m（m>=0）棵互不相交的树的集合称为森林；
  - 科判的用处
    - 总览全文结构
      - 只需要将科判的细目收起，便是一个全文的纲目，可以用于总览全文结构。如一个最深处达18级的详科，收起后12级，仅展开前6级，便是一个能展示出全文结构的略科了。详科本来也可展示全文结构，但是太长不便浏览，必须收起细目，缩短长度。
    - 明辨段落层次
      - 科判的层级式结构，能很好地展现出各个段落之间的关系：是并列关系；还是总分的关系。
      - 文中任何一个段落、句子在全文结构之中处于什么样的位置，科判能很好地展示出来。如此一来，学习便不怕迷路了。
    - 细究章句含义
      - 前者是宏观地概视全文，而今则是借助详细的科表，在微观层面上，细究每个句子的含义。一般来说，这需要配合讲解，仅靠科判很需要想象力。
    - 快速定位内容
      - 在纸质书上，我们使用目录来检索内容。但是目录太粗略，而且即使找到页码也要手动翻到那个页面。而科判本身就是一个有层级的详细目录，使用电子科判时，可以通过收起、展开、下钻等方式在各科之间自如跳转，快速精准地到达想要寻找的位置。在阅读大部头经典时，科判的这种优势更加明显。
    - 构建学习系统
      - 科判的最佳呈现之处是电子屏幕，理论上电子屏幕是无限大的，它能呈现的内容也是无穷的。以科判为骨架，我们可以添加进来很多内容，如：原文、注解、图表……通过超链接，更能链接到很多学习资源库，如“电子佛学辞典集成”、“电子佛典集成”、多种汉语词典的一键检索……可以说，学习需要的资料、工具，都可以在电脑里面找到，而“学习系统”的作用，就是聚合、集成这些学习资料、工具。而这一切，都可以以科判为骨架。
    - 培养科判思维
      - 科判之所以发展得起来，必定先有结构严整的经论原文，
    - 任持全文内容
      - 帮助记忆，任持而不忘失。

    - 电子科判的格式
      > 熟悉格式有助于在各个软件之间互相导入
      - OPML（扩展名.opml）
        - 是大纲处理标记语言（Outline Processor Markup Language）的缩写，它是建立在可扩展标记语言（Extensible Markup Language / XML）之上的标记语言，主要用于描述结构化的、树形的层级式文档结构，因此正好可以用于记录层级式结构的科判！
        - 我们这样使用OPML文件：当我们在A软件做好了科判之后，发现B软件的呈现更方便，（或者是A软件制作方便，B软件呈现、使用方便。）因此想要导入B软件。这时，就可以从A软件导出OPML文件（格式为.opml），然后将导出的OPML文件导入B软件。（实际上就是作为一种中转格式来使用。）相关软件有：
          - XMind、MindManager、FreeMind等思维导图软件
            - XMind支持OPML的导入（但是文件太大则导入失败），也支持OPML的导出（但是Note字数太多则只能导出一部分）。
            - 其他两种还没详细试过，这些软件在OPML的导入导出上可能都没有下很多心思去优化，如果效果不理想只能想办法换个软件多尝试了。
          - Dynalist、WorkFlowy、幕布等层级式笔记软件
            - Dynalist支持OPML的导入和导出。导入OPML，先用记事本打开，再全选复制，然后粘贴到Dynalist的编辑页面上就可以了。导出有导出按钮，在文件栏对文件右键即可发现。
            - WorkFlowy和Dynalist一样，只是导出按钮在右上角的菜单里。
            - 幕布的导入是在新建菜单下，导出在右上角的菜单里。
    - 流程
      - 一、寻找录入时所使用的版本
        - 制作电子科判，保证内容的正确性永远是第一要求，因此必须尽量选择精良的版本来录入科判。其次，为了录入的效率，最好使用电子文档。因此，寻找录入版本，首先就是寻找精良的电子版文档。有以下几个方面需要注意：
          - 1.文档出处。电子版文档种类丰富，但是质量相对没有保障，因此需要考察电子文档的出处，有以下几个方面
            - 有正规出处的。比如来自各大机构的官方渠道，如弘化社官网、佛陀教育基金会官网……
            - 经过可靠人士认可的。最好自己成为可靠人士，自己挑选，哈哈。
          - 2.文档基本信息之标注。文档基本信息有：录入底本来源、录入者、版本状态（如：未校、一校）、版本号或版本日期、版本更新说明等。这种基本信息的标注，可以说代表着文档制作者拥有负责任的态度。类似佛经开头的“证信序”，一个文档有了基本信息的标注，也能令人起信。
        - 如果自己难以找到上述那种精良的电子文档，可以再问问别人。（笔者经常在网上搜索文档，网盘里面的佛教资料有几十T。）
        - 如果真的只能找到一些版本不佳的电子档，那也没关系。电子版的一大优点就是可以方便修改，如果能找到不错的纸质版或者电子影印版，那只需要在录入之后校对就行了。（如果没有电子版只有纸质版，也可以使用OCR软件，如ABBYY，识别文本，再行校对。）
      - 二、录入
        - （一）录入格式
          - 1.文档的命名格式
            - 暂且推荐“科判作者+科判标题_版本状态”的模式，如：圆瑛法师《楞严经科·文》_一校
          - 2.文档信息
            - 可以列在标题的注释之中，也可以置于末尾。
              - 原文及作者
              - 科判版本来源、分科者
              - 录入者
              - 录入时所使用的版本的详细信息（电子版版本多样，将电子版分享出来以供存档就更好了）
              - 版本状态（如：未校、一校）、版本号及版本日期
              - 版本更新说明
          - 3.内容格式
            - 科判+原文
              - 原文统一置于最后一级科判的下一级，或者统一置于最后一级科判的注释格式之中。
            - 科判+原文+注疏+讲记/辑注等多重内容
              - 不论怎么处理，都推荐使用统一的式样，各重内容都有明显区分。这样便于使用程序识别、导出、转换内容，便于在各种程序之间流通。
        - （二）录入技巧
          - 这是一种比较机械、枯燥的事情，掌握一些方法可以提高效率、保护视力。
            - 1.保护视力
              - 使用“蓝光过滤”软件
                - Windows 10已经内置了“夜灯”功能，设置一下就行了
                - 最著名的的蓝光过滤软件是[f.lux](http://www.iplaysoft.com/flux.html)
              - 多休息眼睛，比如[眼保健操](http://music.163.com/m/song?id=427417000)
              - 使用Dynalist时，可以在设置中更改软件主题到“Sepia”或“Dark”
            - 2.其他设置
              - 在Windows系统中，可以快捷地将两个窗口并排显示，快捷键是`Windows（田字）+方向键`，或许有点帮助。
              - 或许可以将大段文字粘贴到科判软件中，然后使用`Enter`及`Tab`等键来分节、缩进，可以免去跨应用复制粘贴之痛苦。
              - 在录入一段时间之后，可以对电子文档作一些改动，以便于录入。比如批量删除不需要的文字、删除空行、删除空格……
              - 熟悉Dynalist的各种快捷键。
        - （三）其他事项
          - 录入经常会遇到原文的科判有小错误，或者原文有小错误，可以使用`Shift+Enter`新建批注，标明问题。总之对底本的任何改动，都需要标明，这是负责任的表现。
      - 三、校对
        - 最好使用较为可靠的版本来校对，要比较什么版本好是一个比较专门的问题，笔者也不太懂。不过，科判使用得熟了，也对该经典较熟悉了，当然会知道什么版本错讹少。
        - 最好多人多次校对，这样出现疏漏的情况会大大减少，保证电子版本的质量。
    - 难点
      - 位于母科下的正文，如何处理
      - 多重内容，如何处理
